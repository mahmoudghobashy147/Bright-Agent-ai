# الردود المحفوظة بدون رسوم نموذج

محرك التشغيل الحالي deterministic داخل الخادم ولا يستدعي OpenAI. لا يحتاج API key أو تنزيل نموذج على جهاز المستخدم. هذا لا يلغي تكاليف استضافة Firebase أو مزود واتساب إن وُجدت.

صاحب الشركة أو مديرها يحفظ قائمة حتى 30 سطرًا من لوحة إعداد الموظف. كل سطر `عبارة | إجابة`؛ العبارة حتى 120 حرفًا والإجابة حتى 500 حرف. مثال توضيحي لا يمثل بيانات شركة حقيقية:

```
مواعيد العمل | يرجى مراجعة فريق الشركة لتأكيد المواعيد
```

المطابقة تطبع حروف العربية وتراعي حدود الكلمات. عند غياب تطابق أو تطابق إجابات مختلفة يرجع النظام نص مراجعة ثابتًا وعلامة requiresReview؛ لا يخترع جوابًا ولا يؤكد تنفيذ طلب. لا يوجد فهم توليدي أو إخطار تلقائي لموظف بشري. ردود واتساب تبقى مسودات في انتظار المراجعة، وضابط الإرسال الفعلي يظل مغلقًا.

زر «اختبار بدون إرسال» يستخدم الردود المحفوظة للشركة من الخادم، لا يحفظ محادثة ولا يستهلك الحصة ولا يتواصل مع خدمة خارجية. يلزم حفظ الإعدادات قبل الاختبار. نقطة المحادثة العامة تبقى مغلقة في الإنتاج حتى اختبار القبول؛ لم تُفتح ضمن هذا التعديل.

نجحت مجموعة npm test المحلية، بما فيها 24 اختبارًا في tests واختبارات cloud وdesktop القديمة، وتُرك اختبارا المحاكيات للتشغيل في CI. اختبارات إضافية تغطي عزل الشركات، رفض المستخدم الغريب، تطبيع العربية، تطابق كلمات مستقلة، تعارض الأجوبة، والتحقق من عدم إنفاق الحصة في المعاينة.

الحالة: نُشر build-2026-10-31-003 وأصبح Current على Firebase App Hosting بعد عودة إتاحة المتصفح. اختُبر بحساب حقيقي داخل شركة اختبار القبول: حفظ ردين، اختبار عبارة مطابقة فأرجعت الرد المحفوظ، واختبار عبارة مجهولة فأرجعت تحتاج مراجعة. بعد reload نجحت قراءة نفس الرد واختباره مرة أخرى. لا رسائل أُرسلت ولا مدفوعات نُفذت. محادثة الجمهور وWhatsApp الفعلي ما زالا غير مفعّلين، ولا إعلان جاهزية تجارية.
