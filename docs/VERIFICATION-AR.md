## مراجعة Firebase الفعلية بعد تسجيل الدخول

تم الوصول بنجاح إلى Firebase Console ومشروع bright-33420 بالحساب الذي اختاره المستخدم. لوحظ الآتي قراءة فقط:

- المشروع الحالي Bright وخطة Blaze مفعلة.
- Email/Password مفعل بالفعل في Firebase Authentication.
- تكوين تطبيق Web المسجل يطابق cloud/console/firebase-config.js، بما في ذلك projectId وappId وauthDomain وstorageBucket. لا حاجة لإنشاء تطبيق جديد لمجرد تغيير الاسم التجاري.
- قبل التنظيف، كان Firestore الافتراضي قائمًا في nam5 وتظهر مجموعتا companies وowners. حذفتا لاحقًا حسب قسم الحالة الأحدث أعلاه. لم يُنشأ تصدير بيانات.
- القواعد الحالية خاصة بمسارات CRM، ولا تتضمن سماحًا عامًا شاملًا. مسارات brightAi* الجديدة تظل ممنوعة على عميل الويب بغياب قواعد سماح لها، وهو السلوك المطلوب لأن الوصول عبر خادم Admin SDK.
- استضافة Firebase القائمة ما زالت تحمل الإصدار القديم؛ لم تستبدل بواجهة Bright Ai ولم تنشر قواعد أو تعدل حسابات.

عائق النشر الحالي: واجهتا shell.cloud.google.com وconsole.cloud.google.com تعرضان Site Unavailable في المتصفح المتاح، بينما Firebase Console نفسه يعمل. جُرب فتح Cloud Shell المضمن ثم فتحه مباشرة، وكذلك واجهة Cloud Run؛ لم تتوفر بيئة نشر عاملة. هذا عائق وصول من بيئة العمل الحالية وليس دليلًا على توقف خدمات Google أو نجاح ربط الخادم.

لم تنشأ مفاتيح خدمة أو تفويضات IAM أو حسابات Super Admin جديدة، ولم تمنح وصولًا جديدًا لتجاوز العائق. المطلوب التالي هو توفير قناة نشر مصرح بها إلى Google Cloud، ثم إنشاء/اعتماد هوية خادم محدودة واختبار Firebase من الخادم نفسه. تسجيل دخول Console ومطابقة الإعدادات لا يعوضان هذا الاختبار.
